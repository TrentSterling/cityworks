# Observed upstream data flow

Source pins: NY `13dd142b480bcfa01a6b18e36127c87e41cb4d80`; SG `69c6329da3cab9c1b1f6a81ceeb1f3dfeb3db13c`. These are code observations; proposed Cityworks changes are in the separate contract.

## New York

1. [`tools/geo-base.mjs`](https://github.com/mrdoob/slop-newyork/blob/13dd142b480bcfa01a6b18e36127c87e41cb4d80/tools/geo-base.mjs) reads borough boundaries, NYC CSCL street centerlines, parks and OSM supplementary features. Longitude/latitude is projected to a local ellipsoidal tangent plane, then rotated into Manhattan's grid. One unit is one metre, x is grid east, z is grid south. The frame starts from longitude −73.98185, latitude 40.75318, bearing about 29°, then refines its avenue bearing and Fifth Avenue/42nd Street origin from source geometry. It is not raw longitude/latitude and not universal EPSG web Mercator.
2. `geo-streets.mjs`, `geo-blocks.mjs`, `geo-roadgraph.mjs` and `geo-extra.mjs` produce `nyc-geodata.js`. Blocks come from land after waterfront reservation and road-width corridor subtraction; sidewalk erosion produces lot interiors. **Numbered streets and avenues are separate layers.** The road graph primarily covers lower Manhattan and selected non-grid roads. Using only that graph omits much of the Manhattan grid. The comparison importer explicitly includes all three.
3. [`tools/build-buildings.py`](https://github.com/mrdoob/slop-newyork/blob/13dd142b480bcfa01a6b18e36127c87e41cb4d80/tools/build-buildings.py) independently reads NYC OTI surveyed building footprints (`5zhs-2jue`). It filters feature codes, converts `height_roof` feet to metres, rejects nonpositive/nonfinite heights, projects `the_geom`, repairs invalid input geometry, and centroid-tests Manhattan inclusion. Construction year comes from `construction_year` or a supplemental BIN lookup; valid years are rounded to decades, otherwise 0. Geometry is simplified and quantized to 0.5 m, with topology repair when that grid changes it. Candidate BIN participates in sort order but is not retained as a runtime ID.
4. `building-geodata.bin.gz` uses NYB1 metadata plus separate delta-varint x/z streams. `building-geodata.js` reconstructs `{height, year, polygons:[{outer,holes}], minX,maxX,minZ,maxZ,cx,cz}`. Coordinates are 0.5 m; height is whole metres. There is no runtime use/type field, terrain base, stable business ID or explicit frontage.
5. [`js/buildings.js`](upstream/nyc/buildings.js) filters authored landmark reserves and groups buildings into five facade materials using year and a center-derived random value. Unknown year takes the modern-material branch. Detail selection uses `round(cx*31 + cz*17)` as seed. Neighbor reserves occupy 128 m cells; a quadtree streams details within 560 m and refreshes after 18 m of focus movement. Details include collision-aware rooftop equipment and fire escapes, plus awnings and cornices. NYC landmarks, Central Park and Times Square billboards are special cases, disabled by this experiment's config shim.
6. [`building-footprints.js`](upstream/nyc/building-footprints.js) groups facade/roof geometry by material and 1 km cell. Outer and hole winding are normalized; holes are passed to `ShapeUtils.triangulateShape`. Every wall has explicit metric length/height and `facadeWall` coordinates, so window bay scale follows wall length at any rotation. Records are extruded from y=0.22 to height+0.22. An explicit `seed` is accepted here; otherwise bucket ordinal determines facade variation. This does not make all other upstream detail randomness ID-based.
7. `main.js` combines city grid, buildings, authored landmarks, street detail, traffic and other systems, then uses scene culling and streamed details. `lighting.js` provides physical sky, environment, sun and time presets; the app adds screen-space reflections and post-processing separately. This spike runs the building/detail path and original lighting, not the complete game assembly.

## Singapore fork

[`tools/city/build.mjs`](https://github.com/zz85/slop-singapore/blob/69c6329da3cab9c1b1f6a81ceeb1f3dfeb3db13c/tools/city/build.mjs) supports configured OSM snapshots and emits GEO v2 in a city-local metre frame. `geodata.js` selects `?city=<id>`, with `nyc` available separately. `open-city-config.js` supplies land and block indexes and disables NYC-specific compatibility features.

GEO v2 contains land polygons `[outerFlat,...holeFlats]`, water, detail boundary, parks, districts, places, labels, blocks and a road graph. Graph nodes are flat x/z values; links are `[a,b,nameIndex,width,lanes,direction,innerShapeFlat,classIndex,level,overWater]`. `osm.mjs` splits streets at shared source node IDs; `graph.mjs` preserves keyed topology. Crossing lines with different IDs do not magically become intersections.

The building builder uses OSM `height`, `building:levels` × 3.2, or documented type/district estimates. `min_height` or `building:min_level` supplies the bottom. It handles `building:part`, excludes some parent outlines, and treats canopies separately. Its centroid land test does not prove that the full footprint avoids roads, water or other buildings. Those are producer responsibilities for synthetic input.

`GEO.buildings` packs rings, top/bottom decimetres and a type index, followed by first-point and within-ring deltas. Outer rings are clockwise; holes are anticlockwise. Data is ordered by 64 m cells. No year or stable ID survives this encoding.

[`open-city-buildings.js`](upstream/singapore/open-city-buildings.js) decodes that payload, picks facade from type, height and district, renders one instanced wall mesh per facade and merged roofs, and returns no-op detail streaming. Courtyard walls are geometric holes, but its returned map footprints omit holes. Short edges below 0.4 m are skipped for walls. Facade seed depends on decoded ordinal `bi`, so insertions can alter unaffected facades.

Missing buildings file produces `null`; `buildOpenCityBuildings` returns null, so `main.js` falls back via `(CITY.open && buildOpenCityBuildings(scene)) || buildCityBlocks(scene)`. A present empty file produces `{types:[],data:[]}`; its builder returns a truthy empty group and suppresses procedural fallback. The harness explicitly tests the supplied-footprint path and does not claim to validate the fallback generator.
